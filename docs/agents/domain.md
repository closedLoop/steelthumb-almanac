# Domain docs

This repository uses a single-context layout:

- CONTEXT.md at the repository root for domain vocabulary.
- docs/adr/ for architectural decisions.

Before exploring, read CONTEXT.md and ADRs relevant to the task.
If they do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

Use the glossary's terms in tickets, proposals, hypotheses, and tests.
Reconsider unfamiliar terminology or note a genuine glossary gap
for domain-modeling.

Explicitly identify conflicts with existing ADRs and explain why
a decision should be revisited.
